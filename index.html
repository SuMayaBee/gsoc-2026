The project in one line

From “run this code” to “check the result first.”

Panel Live Server now lets an assistant render a private draft, inspect a screenshot, refine it when needed, and show the validated result only when it is ready.

MCPPanelPlaywrightPython

What I set out to improve

Useful in real clients, not only on the happy path.

I worked across the MCP server, screenshot pipeline, rendered-result interface, command-line setup, tests, documentation, and project communication.

The goal was practical: reduce friction for people using many different MCP clients, make rendering reliable across Python environments, and make the assistant’s output easier to inspect before a user sees it.

A visual feedback loop

The screenshot feature is not just an export button.

This is the central workflow I introduced. It gives the assistant a practical way to spot layout problems such as clipped labels, crowded dashboards, unsuitable chart types, or missing titles before publishing a result.

01
Write PythonThe assistant creates visualization or Panel app code.
02
Render a draftThe screenshot tool stores the result privately.
03
Inspect visuallyA screenshot goes back to the assistant for review.
04
Refine if neededIt can adjust code and repeat the review loop.
05
Show onceThe approved draft is promoted without double publishing.

Implemented through PR #51, building on the screenshot tool in PR #17 and clearer rendering modes in PR #12.

Four connected streams of work

Features are only useful when the whole path holds together.

01 / VISUAL FEEDBACK

Draft screenshots for real Panel apps

I added private draft rendering, full-page and multi-page dashboard screenshots, plus the browser setup needed for screenshots to work outside development environments.

02 / RELIABILITY

Safer work across environments

I fixed cross-environment server conflicts, isolated Bokeh validation work from live sessions, and restored package checks required in the display and screenshot paths.

03 / PRACTICAL MCP USE

Measured cost, then changed course

I added token-cost reporting and used it to replace expensive inline embeds with an explicit browser action for clients where embedded HTML was not sustainable.

04 / SETUP & GUIDANCE

Less manual configuration

I added configurable prompts, improved user-facing result controls, wrote documentation, and expanded pls install from four to fourteen MCP clients.

How the work grew

A project shaped by testing real behaviour.

Several of the most useful changes came from reproducing what happens in actual clients and environments, then improving the implementation rather than accepting the first workaround.
